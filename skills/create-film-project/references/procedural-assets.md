# Procedural assets

Build every visual and audio asset in code. Nothing in this skill calls an external model-generation, image-generation, or text-to-speech service, and no step requires an API key.

## Characters and props

- Compose meshes from primitive geometry: `capsuleGeometry`, `boxGeometry`, `cylinderGeometry`, `sphereGeometry`, `latheGeometry`, and `ExtrudeGeometry` built from a `THREE.Shape` silhouette.
- Distinguish characters through proportion, palette, and silhouette rather than surface detail: vary limb/torso scale, color (drawn from the story bible's `style.palette` or a character-specific accent), and headwear/props.
- Group primitives for one bible ID under a single named component in `src/lib/characters/<id>.tsx`, so every shot referencing that ID renders identical geometry. Import the component from shots; never re-declare a character's geometry inline in a scene.
- Rig procedural motion (walk cycles, idle sway, blinks, camera-relative facing) with `useCurrentFrame()` and `interpolate()`/sine curves — never randomness without a fixed seed, and never wall-clock time.
- Build materials from `meshStandardMaterial`/`meshPhysicalMaterial` props (`color`, `roughness`, `metalness`, `emissive`) and, where a surface pattern is needed, a procedural `CanvasTexture` drawn with the 2D canvas API — not an image file.

## Environments

- Build sets from primitive geometry (planes, boxes, extruded shapes) composed in `src/lib/locations/<id>.tsx`, keyed by the bible's location IDs.
- Reuse a location's registered component across every shot set there; change its state only through a timeline `stateChanges` event, never by forking the component.

## Dialogue

- No speech-synthesis engine is used natively, so dialogue is delivered as on-screen captions synced to each shot's `dialogue` entries instead of a voiced audio track.
- Each `dialogue` entry has `characterId`, `line`, `startFrame`, and `durationFrames` (frame offsets relative to the shot's own start, since `useCurrentFrame()` inside a `<Sequence>` is already shot-relative).
- Render captions with a shared `Captions` component (see `src/components/Captions.tsx` in the starter project) that looks up the speaking character's name from the story bible and fades the line in/out across its frame range.
- If the user supplies pre-recorded voice lines, treat them like any other provided asset: reference the file path in the asset manifest with `source: "provided"` and play it with Remotion's `<Audio>` — captions stay in sync as the transcript either way.

## Audio synthesis

- Generate music beds, tones, and sound-effect textures with `scripts/synthesize_audio.mjs`, a dependency-free Node script that synthesizes PCM samples (`sine`/`triangle`/`sawtooth` oscillators, or filtered noise for wind/static/footsteps) and writes a standard WAV file. It ships with every project generated by `scripts/init_film_project.py`.
- Run it as a build step, not during rendering — audio must exist as a real file before Remotion's `<Sequence>`/`<Audio>` tree references it, since frame-by-frame video capture cannot drive a live audio graph deterministically.
- Example: `node scripts/synthesize_audio.mjs public/assets/audio/hero-theme.wav --duration 4 --freq 220 --wave triangle --fade 0.3` or `... --wave noise --lowpass 0.15` for a wind bed.
- Record every synthesized cue in `story/asset-manifest.json` with `source: "procedural"` and the parameters used, so it can be regenerated deterministically. Layer multiple synthesized cues and mix in Remotion's `<Audio>`/`<Sequence>` volume controls rather than trying to synthesize a full mix in one pass.
